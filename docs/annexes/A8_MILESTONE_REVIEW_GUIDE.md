# 附录 A8 — 里程碑评审指南：如何评审、关键指标与退出准则

> **适用产品**：可穿戴 AI 相机（类 Looki）  
> **适用对象**：非硬件背景创始人、项目经理、全职能团队  
> **文档目的**：提供每个开发阶段的评审框架、具体评审维度、通过标准和退出准则，确保产品开发每一步都有据可依、风险可控。

---

## 1. 评审总论

### 1.1 评审的目的

评审**不是走形式**，不是"开个会签个字"。评审的核心目的是：

| 序号 | 目的 | 说明 |
|------|------|------|
| 1 | **风险识别** | 在问题还可以低成本修正时发现它 |
| 2 | **信息对齐** | 确保所有角色对当前状态有一致认知 |
| 3 | **决策Gate** | 明确判断是否可以进入下一阶段 |
| 4 | **责任明确** | 遗留问题必须有Owner和Deadline |
| 5 | **知识沉淀** | 把决策逻辑和trade-off记录下来 |

**创始人必须理解的一点**：每跳过一次评审，后面修正的成本至少翻10倍。ID阶段发现造型问题改PPT就行；开模后发现问题，改一次模具5-15万RMB + 2-4周时间。

### 1.2 评审参与角色

| 角色 | 职责 | 人数 | 谁来担任（类Looki团队） |
|------|------|------|--------------------------|
| **决策者 (Decision Maker)** | 最终拍板GO/NO-GO | 1人 | CEO或CTO |
| **评审员 (Reviewer)** | 提出专业意见、打分 | 3-7人 | 各职能负责人(HW/SW/AI/QA/PM) |
| **汇报人 (Presenter)** | 准备材料、汇报进展 | 1-2人 | 该阶段Owner(如ME/EE/SW Lead) |
| **记录人 (Recorder)** | 记录会议结论和Action Items | 1人 | PM或PMO |
| **列席 (Observer)** | 旁听学习，不参与投票 | 0-N人 | 工厂代表、认证顾问等 |

### 1.3 评审输出（四种结论）

| 结论 | 含义 | 后续动作 |
|------|------|----------|
| **GO** | 全部满足，进入下一阶段 | 启动下一阶段计划 |
| **Conditional GO** | 大部分满足，有少量遗留项 | 限期关闭遗留项（通常1-2周），无需再次集体评审 |
| **NO-GO** | 关键项不满足，需要返工 | 制定返工计划，重新准备后再次评审 |
| **KILL** | 方向性错误或不可行 | 终止该方案，启动备选方案或项目复盘 |

**重要原则**：
- Conditional GO的遗留项**必须**有明确Owner + Deadline + 验收标准
- 连续两次NO-GO必须升级到CEO层面决策
- KILL不是失败，是止损，要有勇气做这个决定



### 1.4 评审流程模板（标准六步法）

```
┌─────────────────────────────────────────────────────────────────┐
│  Step 1: 会前准备（评审前3个工作日）                              │
│  ├── 汇报人发出评审材料包（PPT/文档/测试报告/样品照片）          │
│  ├── 评审员提前阅读材料，准备问题                                │
│  └── 记录人发出会议通知（时间/地点/议程/材料链接）               │
│                                                                   │
│  Step 2: 汇报（30-45分钟）                                       │
│  ├── 汇报人按模板汇报（目标→完成情况→遗留问题→风险→建议）       │
│  └── 过程中不打断（除非有事实性错误）                            │
│                                                                   │
│  Step 3: 提问与讨论（30-60分钟）                                 │
│  ├── 每位评审员轮流提问                                          │
│  ├── 汇报人回答或记录为遗留问题                                  │
│  └── 重点讨论有分歧的项                                          │
│                                                                   │
│  Step 4: 打分（10分钟）                                          │
│  ├── 每位评审员独立对每个维度打分（Pass/Fail/Waiver）            │
│  └── 汇总打分结果                                                │
│                                                                   │
│  Step 5: 决策（10分钟）                                          │
│  ├── 决策者综合打分结果和讨论情况做出结论                        │
│  └── 宣布 GO / Conditional GO / NO-GO / KILL                     │
│                                                                   │
│  Step 6: 闭环（评审后2个工作日内）                               │
│  ├── 记录人发出评审纪要（结论+Action Items+Owner+Deadline）      │
│  ├── 所有与会者确认纪要                                          │
│  └── Action Items进入项目跟踪系统                                │
└─────────────────────────────────────────────────────────────────┘
```

**评审时间规划建议**：
- ID评审：1.5-2小时
- DFM评审：2-3小时（最复杂，需要逐项过）
- EVT退出评审：3-4小时（全功能Review）
- DVT退出评审：3-4小时
- PVT退出评审：2小时

## 2. ID 评审（工业设计评审）

### 2.1 基本信息

| 项目 | 内容 |
|------|------|
| **When** | Phase 1 末（约M3-M4） |
| **前置条件** | ID概念方案完成，至少有3个方向的渲染图和手板 |
| **参与人** | CEO, PM, ID设计师, ME工程师, 用户代表(至少2人) |
| **时长** | 1.5-2小时 |
| **输出物** | ID评审纪要 + 选定方向 + 修改意见清单 |

### 2.2 评审维度表（12项）

| 序号 | 评审项 | 评审问题 | 通过标准 | 验证方法 | 权重 |
|------|--------|----------|----------|----------|------|
| 1 | **品牌一致性** | 造型是否符合品牌定位（科技/时尚/亲和）？ | CEO和PM一致认可品牌调性匹配 | 主观评审 + Mood Board对比 | 10% |
| 2 | **用户感知** | 第一眼看到产品时的情感反应是什么？ | ≥70%用户代表给出正面反馈（想买/有兴趣） | 用户访谈或快速问卷(N≥5) | 15% |
| 3 | **人机工学** | 佩戴方式是否自然？操作是否直觉？ | 新用户3秒内能正确佩戴；单手可完成所有操作 | 手板佩戴测试 + 观察 | 12% |
| 4 | **可制造性评估** | ME是否确认此造型可以在预算内实现？ | ME签字确认无不可制造特征，或已标注需要修改的区域 | ME书面意见 | 10% |
| 5 | **CMF可行性** | 颜色/材质/表面处理是否可批量实现？ | 每种CMF方案都有供应商确认可行性和报价 | 供应商反馈记录 | 8% |
| 6 | **竞品差异化** | 与市面竞品(Humane Pin/Ray-Ban Meta等)有明显视觉差异？ | 盲测时≥80%受试者能区分出本产品 | 竞品对比图 + 盲测 | 10% |
| 7 | **成本预估** | 外观件成本是否在BOM预算范围内？ | 外观件总成本≤BOM目标的25%（含模具摊销） | ME/采购初步报价 | 8% |
| 8 | **佩戴舒适度** | 长时间佩戴是否舒适？ | 连续佩戴30分钟无明显不适感 | 手板佩戴测试(N≥3人) | 12% |
| 9 | **社交接受度** | 在社交场景中佩戴是否引起他人反感？ | ≥60%受试者表示"可以接受他人佩戴此设备" | 场景模拟测试/问卷 | 8% |
| 10 | **隐私告知设计** | 是否有明确的拍摄指示灯/隐私提示设计？ | 有可见的LED指示灯设计，1.5米外可辨识 | 手板验证 + 法规合规check | 5% |
| 11 | **尺寸约束** | 外观尺寸是否满足内部堆叠空间需求？ | 内部可用空间≥PCB+电池+传感器所需空间(ME确认) | 3D空间分析 | 7% |
| 12 | **可维修性考虑** | 外观设计是否允许后续拆解维修？ | 至少有一种不破坏外观的拆解方案 | ME拆解方案说明 | 5% |



### 2.3 ID评审的常见坑和注意事项

| 序号 | 常见坑 | 后果 | 对策 |
|------|--------|------|------|
| 1 | **CEO一言堂** | 设计师不敢提反对意见，用户需求被忽视 | 引入用户代表投票，CEO最后发言 |
| 2 | **只看渲染图不看手板** | 渲染图可以骗人，实物比例/质感差距大 | 必须有1:1手板(哪怕3D打印的) |
| 3 | **忽略可制造性** | 漂亮的设计开不了模或成本翻倍 | ME必须参与ID评审，当场给反馈 |
| 4 | **忽略佩戴场景** | 静态好看但运动时会掉/晃动 | 测试场景必须包含走路/跑步/低头 |
| 5 | **颜色选择靠屏幕** | 屏幕色彩和实际喷漆/阳极氧化色差大 | 必须用实物色板确认，考虑不同光线环境 |
| 6 | **忽略隐私设计** | 上市后被媒体/监管攻击 | 隐私指示灯必须在ID阶段就设计进去 |
| 7 | **尺寸过于激进** | 内部空间不够，后续不得不加大 | ID评审时ME必须确认内部空间裕度≥10% |
| 8 | **没有考虑配件** | 主机好看但充电座/包装不搭 | ID评审范围应包含全套配件 |

## 3. DFM 评审（可制造性评审）

### 3.1 基本信息

| 项目 | 内容 |
|------|------|
| **When** | ID定稿后 → 开模前（Phase 1-2 交界，约M4-M5） |
| **前置条件** | ID冻结、3D结构初步完成、模具供应商已初步沟通 |
| **参与人** | ME Lead, EE Lead, 模具工程师, 工厂PM, QA |
| **时长** | 2-3小时（最耗时的评审，需逐项过） |
| **输出物** | DFM评审报告 + 模具开模确认 + 风险清单 |

### 3.2 为什么DFM评审最关键

对于类Looki这样的小型可穿戴设备，DFM评审是**成本和时间风险最高**的Gate：
- 一副模具费用：5-20万RMB
- 模具修改一次：1-5万RMB + 2-4周
- 如果DFM没做好就开模，可能需要2-3次修模，白白浪费30-60万和2-3个月

### 3.3 评审维度表（18项）

| 序号 | 评审项 | 具体检查内容 | 通过标准 | 不通过的后果 | Owner |
|------|--------|-------------|----------|-------------|-------|
| 1 | **壁厚均匀性** | 所有塑胶件壁厚是否均匀？有无薄壁区域？ | 壁厚变化≤30%，最薄处≥0.8mm（PC/ABS材料） | 缩水、应力集中、翘曲 | ME |
| 2 | **出模角(拔模角)** | 所有面是否有足够的出模角？ | 外观面≥1°，非外观面≥0.5°，深腔结构≥2° | 拉伤、脱模困难、外观缺陷 | ME |
| 3 | **分型线位置** | 模具分型线是否在不影响外观的位置？ | 分型线在非可见面或自然过渡线位置 | 外观瑕疵、客诉 | ME+模具 |
| 4 | **顶针位置** | 顶出位置是否合理？ | 顶针在非外观面，顶出面积足够，顶出均匀 | 顶白、变形 | 模具 |
| 5 | **倒扣(Undercut)处理** | 所有倒扣结构是否有脱模方案？ | 每个倒扣都有明确的滑块/斜顶/强脱方案 | 无法脱模或模具过于复杂 | ME+模具 |
| 6 | **装配顺序** | 是否有明确的装配顺序？有无干涉？ | 装配步骤≤15步，无需特殊工具（除螺丝刀） | 产线效率低、良率差 | ME |
| 7 | **连接方式选择** | 螺丝/卡扣/超声焊/胶粘的选择是否合理？ | 每个连接点都有明确的连接方式+理由+可维修性评估 | 强度不足或无法维修 | ME |
| 8 | **PCB堆叠可行性** | PCB的层数、大小、连接器位置是否可装入壳体？ | PCB和壳体之间余量≥0.3mm，FPC走线有空间 | 装不进去或挤压损坏 | ME+EE |
| 9 | **天线净空区域** | WiFi/BT/GPS天线周围是否有足够净空？ | 天线净空区域内无金属件，距离金属≥3mm | 射频性能严重下降 | EE+ME |
| 10 | **散热路径** | 主芯片散热路径是否设计好？ | 芯片→导热垫→金属件(或壳体)路径通畅 | 过热降频或安全风险 | ME+EE |

| 11 | **防水密封方案** | IP等级要求下的密封方案是否可行？ | IPX4: 所有开孔有防水膜/密封圈；密封件压缩量15-25% | 进水损坏、客诉 | ME |
| 12 | **磁吸结构** | 磁铁规格/位置/固定方式是否明确？ | 吸附力≥设计要求(如≥3N)，磁铁有防脱落措施 | 掉落、磁铁对电子器件干扰 | ME |
| 13 | **公差链分析** | 关键配合尺寸的公差累积是否在可接受范围？ | 公差链分析完成，最坏情况仍可装配，CPK≥1.33 | 装不上或间隙过大 | ME |
| 14 | **表面处理可行性** | 喷漆/电镀/阳极氧化/IMD等方案是否可行？ | 有供应商确认可行性+样板+报价 | 外观达不到效果或成本超标 | ME+ID |
| 15 | **注塑材料选择** | 材料是否满足力学/外观/成本/环保要求？ | 材料datasheet满足设计要求，有备选材料 | 性能不达标或环保不合规 | ME |
| 16 | **FPC/线缆走线** | 柔性电路板和线缆走线路径是否合理？ | 弯折半径≥规格要求，无挤压风险，有固定方案 | 断线、信号干扰 | ME+EE |
| 17 | **充电接口/触点** | 充电方案的结构实现是否可行？ | 触点接触可靠(弹片行程0.3-0.5mm)，防水达标 | 充电不良、进水 | ME+EE |
| 18 | **跌落保护设计** | 关键部件(镜头/屏幕)是否有跌落保护？ | 有缓冲结构设计，镜头不直接接触地面 | 跌落碎裂 | ME |

### 3.4 DFM红线（绝对不能妥协的项）

以下为**一票否决**项，任何一项不通过即为NO-GO：

| 红线编号 | 红线项 | 原因 |
|----------|--------|------|
| R1 | 存在无法脱模的结构 | 物理上不可制造 |
| R2 | PCB装不进壳体 | 项目根本无法完成 |
| R3 | 天线被金属完全包围 | 射频无法工作 |
| R4 | 散热路径完全阻断 | 安全风险（起火/烫伤） |
| R5 | 壁厚＜0.5mm(注塑件) | 注塑充不满 |
| R6 | 无防水密封方案但有IP要求 | 无法通过认证 |
| R7 | 公差链累积后无法装配 | 良率为0 |

## 4. MD 评审（结构设计评审）

### 4.1 基本信息

| 项目 | 内容 |
|------|------|
| **When** | 结构3D定稿后 → 开模前（与DFM可合并或紧接其后） |
| **前置条件** | 3D模型完成、仿真分析完成、装配动画完成 |
| **参与人** | ME Lead, EE Lead, 模具供应商代表, QA, PM |
| **时长** | 2-3小时 |
| **输出物** | 结构设计评审报告 + 仿真报告确认 + 开模启动确认 |

### 4.2 MD评审与DFM评审的区别

| 维度 | DFM评审 | MD评审 |
|------|---------|--------|
| 关注点 | 能不能制造 | 设计是否满足性能和可靠性 |
| 深度 | 模具工艺层面 | 结构性能层面 |
| 依据 | 制造工艺规范 | 仿真数据+设计计算 |
| 参与者侧重 | 模具工程师主导 | ME主导 |

### 4.3 评审维度表（12项）

| 序号 | 评审项 | 评审内容 | 通过标准 | 验证方法 |
|------|--------|----------|----------|----------|
| 1 | **结构强度仿真** | 关键部件在典型载荷下的应力分布 | 安全系数≥2.0，最大应力＜材料屈服强度50% | FEA仿真报告 |
| 2 | **热仿真结果** | 极限工况下的温度分布 | 芯片结温≤85°C，外壳温度≤42°C（贴肤面） | CFD热仿真 |

### 5.5 Bug分类与退出红线

#### Bug严重等级定义

| 等级 | 定义 | 举例（类Looki产品） |
|------|------|---------------------|
| **P0-致命** | 导致设备不可用/安全风险/数据丢失 | 电池过充无保护、设备变砖无法恢复、连续死机 |
| **P1-严重** | 核心功能不可用但设备可工作 | 无法拍照、WiFi无法连接、OTA升级失败 |
| **P2-一般** | 非核心功能异常或性能不达标 | 画质略低于目标、配网偶尔失败、LED颜色不准 |
| **P3-轻微** | 体验类问题，不影响功能 | 动画卡顿、文案错误、非关键场景UI异常 |

#### EVT退出Bug红线

| 红线项 | 标准 | 说明 |
|--------|------|------|
| P0 Bug数量 | **= 0** | 绝对不允许有P0遗留 |
| P1 Bug数量 | **≤ 3** | 且每个P1都有明确修复计划和Owner |
| P1修复计划 | DVT第2周前完成 | 必须有具体的修复方案（不是"继续调查"） |
| P2 Bug数量 | **≤ 15** | 已分类并排优先级 |
| Bug趋势 | 收敛 | 最近一周新增Bug数＜修复Bug数 |

### 6.9 Design Freeze（设计冻结）的含义和流程

#### 什么是Design Freeze？

Design Freeze是指**产品设计的所有方面（硬件/软件/结构/算法）在该时间点后不再做功能性更改**。这是DVT→PVT的最关键Gate。

#### Design Freeze覆盖范围

| 类别 | 冻结内容 | 冻结后允许的修改 |
|------|----------|------------------|
| 硬件 | PCB Layout、原理图、BOM | 仅限安规相关的必要修改 |
| 结构 | 3D模型、模具、CMF | 仅限模具微调(如浇口/冷却水路) |
| 软件 | 功能集合(Feature Set) | 仅限Bug修复，不新增功能 |
| 算法 | 模型版本、参数 | 仅限ISP/音频参数微调 |
| 包装 | 包装设计、配件清单 | 仅限文案/合规标识更新 |

#### Design Freeze签字流程

```
1. ME Lead确认结构冻结 → 签字
2. EE Lead确认硬件冻结 → 签字
3. SW Lead确认功能冻结 → 签字
4. AI Lead确认算法冻结 → 签字
5. PM确认BOM/包装冻结 → 签字
6. CEO/CTO最终确认 → 签字
```

**重要**：Design Freeze后的任何修改都必须走ECN(Engineering Change Notice)流程，由CEO/CTO批准。

### 7.3 PVT关键产线指标详解

#### 良率计算方法

```
整体直通良率(FPY) = SMT良率 × 组装良率 × FCT良率 × 老化良率 × OQC通过率

例：98.5% × 97% × 96% × 99% × 99.5% = 90.3%

目标：FPY ≥ 90%（首批PVT），MP阶段目标FPY ≥ 93%
```

#### UPH(Units Per Hour)计算

```
UPH = 3600s ÷ 瓶颈工站节拍时间(s)

例：瓶颈工站节拍 = 60s → UPH = 60 pcs/h
产线日产能 = UPH × 有效工作时间(如10h) × 产线数 = 60 × 10 × 1 = 600 pcs/day
```

#### OQC抽检标准

| 缺陷等级 | 定义 | AQL | 抽检方案(批量500) |
|----------|------|-----|-------------------|
| Critical(致命) | 安全风险 | 0 | 全检或Ac=0 |
| Major(主要) | 功能缺陷 | 1.0 | 样本50, Ac=1, Re=2 |
| Minor(次要) | 外观瑕疵 | 2.5 | 样本50, Ac=3, Re=4 |

## 9. 关键指标如何确定（方法论）

### 9.1 从用户体验倒推指标

**核心思想**：用户不关心技术参数，只关心体验。所以指标必须从用户体验需求倒推。

#### 案例：续航指标确定

```
用户需求：出门一天不用充电
  ↓
使用场景分析：典型用户一天使用4-6次，每次10-30分钟
  ↓
累计使用时间：约2-4小时有效使用
  ↓
加上待机功耗：16h待机 + 4h使用
  ↓
续航指标：连续使用≥4h 或 混合使用≥16h(含待机)
  ↓
功耗预算分配：
  - 电池容量选择：如580mAh
  - 拍照模式功耗预算：≤145mW (580mAh×3.8V÷4h÷3.8 = ~145mW... 简化计算)
  - 待机功耗预算：≤3mW
  - 各模块功耗分配：
    ┌─────────────┬──────────┬──────────┐
    │ 模块         │ 工作功耗  │ 待机功耗  │
    ├─────────────┼──────────┼──────────┤
    │ SoC          │ 400mW    │ 1mW      │
    │ Camera       │ 150mW    │ 0mW      │
    │ WiFi TX      │ 300mW    │ 0.5mW   │
    │ BT           │ 50mW     │ 0.1mW   │
    │ 其他(LED等)  │ 50mW     │ 0.1mW   │
    ├─────────────┼──────────┼──────────┤
    │ 总计         │ 950mW    │ 1.7mW   │
    └─────────────┴──────────┴──────────┘
  - 验算：580mAh × 3.8V ÷ 950mW ≈ 2.3h (纯拍摄)
  - 需要优化或增大电池
```

#### 案例：画质指标确定

```
用户需求："拍出来能发朋友圈不丢人"
  ↓
翻译为技术需求：
  - 分辨率：≥1080P（朋友圈够用）
  - 日间画质：色彩自然，清晰度好
  - 低光画质：室内(100lux)可用，噪点不明显
  - 动态范围：逆光场景脸不黑
  ↓
量化指标：
  - 分辨率：1920×1080 @ 30fps
  - 日间清晰度：MTF50 ≥ 0.3 (at Nyquist/2)
  - 低光SNR：≥ 30dB @ 100lux
  - HDR动态范围：≥ 80dB
  - 主观评分：≥ 7/10 (盲评)
```

### 9.2 从竞品对标确定指标

**方法**：收集3-5个竞品的关键参数，取平均值作为基线，设定"≥竞品均值"或"Top 2水平"。

#### 竞品对标表示例（类Looki产品）

| 指标 | 竞品A(Humane) | 竞品B(Ray-Ban) | 竞品C(某国产) | 均值 | 我方目标 |
|------|--------------|----------------|---------------|------|----------|
| 重量 | 55g | 49g | 35g | 46g | ≤35g |
| 续航(录像) | 2h | 3h | 1.5h | 2.2h | ≥4h |
| 分辨率 | 720P | 1080P | 1080P | - | 1080P |
| 防水 | 无 | IPX4 | IPX2 | - | IPX4 |
| 充电时间 | 60min | 75min | 45min | 60min | ≤60min |
| 配网时间 | 30s | 15s | 45s | 30s | ≤20s |

**注意**：竞品对标不是唯一标准，如果产品定位不同（如更轻更小），某些指标可以低于竞品。



### 9.3 从法规/认证要求确定指标

**原则**：认证指标是**硬性约束**，没有商量余地。不通过认证 = 不能合法销售。

#### 常见认证指标要求

| 认证 | 关键指标 | 要求 | 备注 |
|------|----------|------|------|
| FCC Part 15 | 辐射发射 | 各频段≤限值 | 美国市场必须 |
| CE RED | 辐射发射+传导 | 各频段≤限值 | 欧盟市场必须 |
| IEC 62368-1 | 产品安全 | 温升/绝缘/接地等达标 | 音视频设备安全标准 |
| UN38.3 | 电池运输安全 | 高度模拟/温度循环/振动/冲击/短路等 | 锂电池运输必须 |
| IEC 62133 | 电池使用安全 | 过充/过放/温度/挤压等 | 含锂电池产品必须 |
| SAR (如适用) | 人体辐射吸收 | ≤1.6W/kg(FCC) / ≤2.0W/kg(CE) | 贴身穿戴可能需要 |
| RoHS | 有害物质 | 铅/汞/镉/六价铬等≤限值 | 环保合规 |

**建议**：在设计阶段就留出**认证余量**：
- EMC：设计目标比限值低6-10dB
- 温升：设计目标比限值低5-10°C
- 电池安全：选择有完整认证的电芯

### 9.4 从制造良率倒推设计余量

**核心概念**：设计中心值和公差决定了量产良率。设计余量越大，良率越高。

#### 设计余量原则

```
设计余量 = (规格上限 - 设计中心值) ÷ 规格范围 × 100%

推荐余量：
- 关键安全指标：≥30%余量
- 关键性能指标：≥20%余量
- 一般性能指标：≥10%余量
```

#### 实例：续航指标余量设计

```
目标续航：4h（用户承诺值）
设计余量：20%
设计目标：4h × 1.2 = 4.8h（内部设计目标）

为什么需要余量？
- 电池容量批次差异：±5%
- 温度影响：低温容量下降10-15%
- 老化衰减：1年后容量下降5-10%
- 功耗波动：不同使用模式±10%

如果设计恰好4h，量产后很多设备实际续航只有3.2-3.5h → 客诉
如果设计目标4.8h，量产后大部分设备实际续航4.0-4.5h → 安全
```

#### Cpk与良率对应关系

| Cpk值 | 不良率(单侧) | 每百万不良数(PPM) | 建议应用场景 |
|--------|-------------|-------------------|-------------|
| 1.00 | 0.135% | 1,350 | 一般指标最低要求 |
| 1.33 | 0.003% | 32 | 重要指标推荐 |
| 1.67 | ~0.0001% | 0.6 | 安全关键指标 |
| 2.00 | ~0.000001% | 0.002 | 零缺陷要求 |

### 9.5 从成本目标确定BOM红线

**逻辑**：售价 → 毛利率目标 → 允许BOM成本 → 各模块BOM分配

#### BOM成本分配示例

```
目标售价（零售）：$199
渠道/营销成本：40%（$80）
毛利率目标：30%（$60）
允许COGS：$59
  ├── BOM成本：$42 (71% of COGS)
  ├── 制造成本：$8 (组装+测试+包装)
  ├── 物流仓储：$4
  └── 损耗/售后预留：$5

BOM $42的分配：
  ┌────────────────┬────────┬──────┐
  │ 模块            │ 预算    │ 占比  │
  ├────────────────┼────────┼──────┤
  │ SoC主芯片       │ $8     │ 19%  │
  │ Camera模组      │ $6     │ 14%  │
  │ 电池            │ $3     │ 7%   │
  │ PCB+SMT        │ $5     │ 12%  │
  │ 结构件(壳体等)  │ $6     │ 14%  │
  │ WiFi/BT模组     │ $4     │ 10%  │
  │ 存储(Flash)     │ $3     │ 7%   │
  │ 传感器(IMU等)   │ $2     │ 5%   │
  │ 连接器/FPC     │ $2     │ 5%   │
  │ 其他(被动器件等)│ $3     │ 7%   │
  ├────────────────┼────────┼──────┤
  │ 总计            │ $42    │ 100% │
  └────────────────┴────────┴──────┘

BOM红线 = $42 × 1.1 = $46.2（允许10%超标缓冲）
超过$46.2必须CEO审批或砍功能
```

### 9.6 指标分级：红线指标 vs 目标指标 vs 挑战指标

| 级别 | 定义 | 不达标后果 | 示例 |
|------|------|-----------|------|
| **红线指标(Must Have)** | 绝对不可妥协，不达标=项目停止 | NO-GO，必须修复 | 安全指标、认证指标、核心功能 |
| **目标指标(Target)** | 正常应该达到，允许少量Waiver | Conditional GO | 续航、画质、成本 |
| **挑战指标(Stretch)** | 做到更好但不强制 | 不影响评审结论 | 超长续航、极致轻量、高级AI功能 |

#### 类Looki产品指标分级示例

| 指标 | 红线 | 目标 | 挑战 |
|------|------|------|------|
| 续航(录像) | ≥2h | ≥4h | ≥6h |
| 重量 | ≤50g | ≤35g | ≤25g |
| 防水 | IPX2 | IPX4 | IPX7 |

| 配网成功率 | ≥85% | ≥95% | ≥99% |

| BOM成本 | ≤$50 | ≤$42 | ≤$35 |

## 10. 评审常见失败模式与对策

### 10大评审失败模式

| 序号 | 失败模式 | 典型表现 | 后果 | 对策 |
|------|----------|----------|------|------|
| 1 | **走形式评审** | "反正CEO已经决定了，评审就是走流程"；没人真正看材料 | 风险被掩盖，后期爆雷 | 评审前强制所有人提交至少3个问题；CEO最后发言避免影响他人 |
| 2 | **关键人缺席** | ME没来DFM评审，或工厂没参加PVT评审 | 缺乏关键视角，决策质量差 | 关键评审员缺席则评审自动延期；提前3天确认出席 |
| 3 | **数据不全/数据造假** | "还没测完""数据在另一台电脑上""测了但结果不太好就没放" | 基于不完整信息决策 | 评审前2天必须提交完整数据包，缺项不开评审；QA交叉验证数据 |
| 4 | **跳过Gate** | "时间太紧了，EVT评审先跳过直接做DVT" | 累积风险到后期集中爆发，损失翻倍 | 坚守Gate制度；如果真要跳过，CEO签字确认风险承担 |
| 5 | **过度乐观偏差** | "这个问题DVT肯定能解决""应该不会有问题" | 系统性低估风险和工作量 | 要求每个"应该能解决"都给出具体方案+时间+Owner；引入Pre-Mortem分析 |
| 6 | **评审颗粒度不够** | 只看"硬件OK"三个字，不深入每个子项 | 隐藏的问题被笼统结论掩盖 | 使用本文档的详细评审表，逐项确认，不允许"打包通过" |
| 7 | **Waiver滥用** | 大量项目都用Waiver放行，"先发货再说" | 上市后品质问题频发，退货/客诉 | 严格限制每次评审Waiver数量(建议≤3项)；每个Waiver必须CEO签字 |
| 8 | **缺乏跟踪闭环** | 评审提出的Action Items没人跟踪，下次评审还是同样的问题 | 评审变得毫无意义 | Action Items必须进入项目管理工具；下次评审第一项就是Review上次遗留项 |
| 9 | **评审范围蔓延** | DFM评审时讨论市场策略，EVT评审时讨论UI设计 | 评审效率低，关键问题被淹没 | 主持人严格控制议题范围；非本次评审范围的议题记录到"停车场"(Parking Lot) |
| 10 | **决策权不清晰** | 评审结束后"到底谁说了算？""老板说GO但QA说NO-GO" | 决策混乱，执行时无所适从 | 评审前明确谁是Decision Maker(只能一人)；Decision Maker不是每项都最懂但必须最终拍板 |

### 对策总结：好的评审的5个特征

```
┌─────────────────────────────────────────────────────────────────────┐
│                    优秀评审的5个特征                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. 有数据：每个结论都有数据支撑，不接受"我觉得""应该"              │
│                                                                      │
│  2. 有标准：通过标准在评审前就定好，不是评审时临时谈判                │
│                                                                      │
│  3. 有Owner：每个遗留项都有明确的责任人和截止日期                    │
│                                                                      │
│  4. 有勇气：敢于说NO-GO，哪怕压力很大（宁可延期不可带病上市）       │
│                                                                      │
│  5. 有闭环：评审结论被执行，Action Items被跟踪到关闭                 │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 评审效能检查清单

每次评审结束后，PM应花5分钟自检评审质量：

- [ ] 评审材料是否提前48h发出？
- [ ] 所有关键评审员是否到场？
- [ ] 是否每个维度都有量化数据？
- [ ] 是否有评审员提出了有价值的新问题？
- [ ] 决策是基于数据还是基于"感觉"？
- [ ] Action Items是否都有Owner+Deadline？
- [ ] 评审纪要是否在24h内发出？
- [ ] 上次评审的遗留项是否都被Review了？
